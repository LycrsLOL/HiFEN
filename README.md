# HiFEN

HiFEN predicts EC1–EC4 enzyme functions from ESM3 residue embeddings and structural residue graphs. The complete model uses **layerwise fusion, parent conditioning, annotation encoding, and structure completion**. Structure completion is performed before graph construction. The prediction network uses four residual GATv2 layers followed by residue-wise layer fusion, annotation encoding, shared attention pooling, and four EC heads with parent conditioning.

The default configuration and direct `HiFENModel` constructor disable functional hypergraph propagation and its associated site-prediction heads. The corresponding site-loss weights are zero. The archived implementation remains available through an explicit model override for older configurations; it is not part of the current complete model or its four ablation profiles.

## Published data partition: Supplementary Table S2

The fixed partition contains **131,013 graph records**:

| Split | Graph records | Distinct full protein identifiers |
|---|---:|---:|
| Training | 104,804 | 101,236 |
| Validation | 13,105 | 12,928 |
| Test | 13,104 | 12,916 |

The original workbook is preserved at [`supplementary data/Supplementary Table S2.xlsx`](supplementary%20data/Supplementary%20Table%20S2.xlsx). The repository's `train_graphs.txt`, `val_graphs.txt`, and `test_graphs.txt` store portable graph basenames. At runtime, these basenames are resolved against the selected profile's `storage.graph_dir`; no server-specific absolute paths are required.

[`splits/s2_membership.csv`](splits/s2_membership.csv) links each S2 row to its full source identifier, PDB identifier, and graph filename. S2 contains 109 abbreviated RefSeq identifiers (`NP`, `WP`, or `XP`); their full identifiers were recovered using exact multiplicities and row-order correspondence with the previous graph manifests, followed by exact filename matching against `data/train.csv`. The original workbook was not rewritten. Partial matches of repeated display identifiers are rejected by the import script.

Compared with the previous manifests, S2 removes 52 training, 2 validation, and 3 test records. These 57 records are listed in [`splits/s2_excluded_graphs.csv`](splits/s2_excluded_graphs.csv). The resolved cohort has no shared homology-cluster, sequence-cluster, full protein, or source-record identifiers across splits. Every EC1–EC4 label observed in validation or test is observed in training. Exact counts, label coverage, and file checksums are recorded in [`split_summary.json`](split_summary.json).

The default `train.fixed_split_dir: .` fixes training and evaluation to S2. Extra prepared graphs are ignored. Missing assigned graphs or modified manifests cause an error, rather than changing the cohort. `force_resplit` is incompatible with this fixed partition. Set `train.fixed_split_dir: null` explicitly when preparing a different cohort. `--limit N` selects the first N assigned records from each split for a smoke run and does not overwrite the full runtime manifests.

The separate 4,172-protein structure-completion experiment uses its own frozen cohort and split files; the S2 partition does not replace that experiment's 3,661/250/261 partition. Historical checkpoints and result tables are not regenerated by changing the default model configuration.

## Installation and training

Use Python 3.10 or newer, with a PyTorch/PyG installation suitable for the target hardware:

```bash
pip install -e '.[test]'
hifen deploy-data --config configs/hifen.yaml
hifen train --config configs/hifen.yaml
```

ESM3 weights, sequence embeddings, structures, and prepared graph caches must be supplied or generated separately. Configure their locations in `configs/hifen.yaml`. The default optimizer is AdamW with learning rate 7.5e-5 and weight decay 0.01. Training uses 32 graphs per process, up to 160 epochs, four warmup epochs, cosine decay, gradient clipping at 0.5, and early-stopping patience 20. The base seed is 42, with process rank added during distributed initialization. Thresholds are calibrated on validation data and fixed for held-out testing.

The four supported single-module ablation profiles are:

- `without_layerwise_fusion`
- `without_parent_conditioning`
- `without_tool_annotations`
- `without_structure_completion`

For example:

```bash
hifen train --config configs/hifen.yaml --profile without_parent_conditioning
```

All four profiles inherit the same S2 membership. The structure-completion profile resolves it against a separate graph cache. It does not define the experimental-only arm of the separate controlled structure experiment.

## Verification and partition import

```bash
python -m unittest discover -s tests -p test_fixed_splits.py
pytest -q tests/test_modules.py
```

The standard-library partition importer requires S2, the source CSV, and the previous manifests:

```bash
python scripts/import_s2_splits.py \
  --s2 'supplementary data/Supplementary Table S2.xlsx' \
  --csv data/train.csv \
  --previous-split-dir /path/to/previous/manifests \
  --output-dir /path/to/new/export
```

It verifies exact record resolution, split separation, and label coverage before exporting the fixed manifests. Use a separate output directory to retain the previous manifests for auditing.
